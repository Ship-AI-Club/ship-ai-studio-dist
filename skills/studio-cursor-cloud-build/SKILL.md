# Cloud build

## 0. Resolve

From this folder run `node ../../scripts/resolve-studio.mjs --skill studio-cursor-cloud-build`. Send the JSON to the PM. Stop on any error; never load an older product-team skill instead.

This applies to the Grok coordinator. An agent already in the assigned Cloud run must implement there and must not launch a nested Cloud agent.

Use the verified PStack and Studio setup before implementation. Cursor Cloud delegation is a built-in capability, not a similarly named plugin. Check team policy if it is missing. Use GitHub only when the selected repository needs it and verify actual access. When a real repository exists, run /create-verification-skill if no suitable verify-* skill exists. Reuse an existing project verifier where available. Do not delete shared private skills to free a slot. Keep complete skills, references, licenses and verification scripts in the source kit and actual Cloud workspace. A Cloud agent already in the assigned run implements there and must not launch a nested run. Record sourceBriefVersion and sourceBriefSha256 from the current PM brief. Map its facts and approval state into site and API contracts without changing their shapes. Do not compare schemaVersion to a content version. Before any push or deployment trigger, run the repository typecheck where applicable, targeted tests and production build on that commit. Record exact commands and exit codes; never use hosting CI as the first compiler. Stop only for a required login, terms or access decision; keep secrets out of chat and exports.

Start approved website implementation in Cursor Cloud automatically after the saved model choice and setup checks. Select the saved setup.siteBuildModel (Studio default Opus 5.5 Medium) at medium effort, Fast off, with the actual Cloud tool selector. Do not require another instruction to delegate. Verify the returned run URL, model and effort before reporting success. In every Cloud run, read the actual Cloud model selector setting (for example "Claude Opus 5.5 Medium", Fast off) and record that exact text as evidence in the handoff and design/gate.json. Never silently substitute another model. Send feedback to the same project and the same run. Never silently use Fast, Auto, another model or local implementation. If the selected model or Cloud capability is unavailable, report the specific blocker to PM and ask for a fallback decision. Keep the business, audience and brand agnostic. Reuse the recorded run for feedback; do not start duplicate runs. Before launch and after each feedback or scope change, get the current PM brief and approved design/copy handoff. Record their versions, approval state and file hashes in a handoff manifest. Send updated files to the same Cloud run and require acknowledgment of the received versions before further implementation. Recover existing approvals from PM; do not ask the owner to repeat them. An initial upload does not carry later decisions. Distinguish an uploaded archive audit from verification of files inside the live Cloud workspace.

Before launch, load the full Next.js starter and verify every path and SHA256 in design-skill-library.json. Use npm run verify:design where supplied; otherwise perform the same full file audit. Stop on missing or changed files. Include hidden .agents/skills/ and .cursor/ folders, AGENTS.md, README.md, the approved shared brief, design handoff, copy, lockfile, manifests, reference files and licenses in the actual Cloud repository or upload. Local skill cards, links and summaries do not supply Cloud context. Exclude secrets, private chats, node_modules, .next and unrelated files. Require the Cloud agent to repeat the file audit inside its workspace, read the applicable actual design/copy files and references, and record what it read. A hash check proves integrity, not that skills were read or applied.

Frontend coordinates the PM, Designer and Cloud agent through studio-design-gate. The Cloud agent first builds ONLY the hero and first proof section from the design contract, as production components written for this page, with the full relevant skills and references actually read and applied. A low-fidelity mock is never labeled premium. It runs npm run build:review and captures desktop (1440px) and phone (390px) screenshots. A separate design reviewer and a separate marketing reviewer critique those renders and reject weak composition, generic branding, poor type, dense copy, weak proof or a CTA mismatch with specific corrections. Frontend revises and re-renders in the same run until both PASS; every round is recorded in design/gate.json. Nothing else is built until both PASS. Then the Cloud agent builds the full site, runs the real checks, build and browser journeys, and Gate 2 reviews every page and visitor state in the contract's Experience inventory (each in-scope route, plus forms with their useful results and errors where in scope) on actual desktop and phone screenshots, and both reviewers cover each one, before the PM shows the owner. Tests, read logs and hashes never pass a gate. Save the run URL, actual model selector text, brief version, file audit and skill-read record with the handoff. Stop before deployment and external sends.
